# Issues 529 and 530

## KTF turn scheduling (#529)

Exact package SHA-256: `82ad4f8139517a8ae4aa81bef2cde8ea5b6898c262d2e031563949c2bf02c04e`.

The turn game's `TimerTask.run()` schedules another callback before returning.
The scheduler treated each callback as an independent worker, allowing the next
callback to run while its predecessor was sleeping or painting. The authorized
package reproduces overlapping callbacks by 300 ms, before any player input.

A Java Timer now retains its worker across callback yields. Unstarted callbacks
are selected by deadline; independent timers and handset input remain runnable.
KTF state schema 16 carries callback ownership, started state, periodic deadlines
and TimerTask status. Schemas 2 through 15 remain readable; they do not contain
the new ownership information.

Synthetic regressions cover sleeping callbacks, independent timers, deadline
order, state round trips, and invalid timer metadata. The optional exact-package
test runs 40 seconds with select-key input and checks that a Timer never has two
started callbacks alive at once.

## BREW menu footer text (#530)

Exact package SHA-256: `1e7753773e3afb794d704bc67f3e70bc58336bfd28cb762094da97e057f8914f`.

The game copies a LoadResString AECHAR label with WSTRCPY, then draws its selected
menu footer using `IDF_TEXT_FORMAT_OEM`. Treating the UTF-16 storage as EUC-KR
produced unrelated characters and stopped at embedded zero bytes, including
before the rest of a label containing a space.

An exact-package compatibility policy reads this footer as AECHAR. Other packages
retain OEM byte decoding. This is a compatibility model for this title's resource
and footer combination, not a change to BREW's OEM text contract. The SDK defines
OEM text as a byte pointer in [AEEIDisplay.h](https://github.com/chinahby/1110/blob/master/main/platform/brew/brewpk/inc/AEEIDisplay.h).

The synthetic regression compares the complete rendering of a wide label with
and without the OEM flag and rejects lookalike package hashes. The optional
private regression replays the report's input timings through 17,360 ms and
checks the footer's pixel hash. These tests establish the reported footer fix;
they do not establish complete native menu-control or game compatibility.

Both private regressions read authorized inputs in place via `ARAM_TEST_DATA`.
No package contents or screenshots are committed.
